# Security policy / 安全策略

## Supported versions / 支持版本

| Version | Security fixes |
| --- | --- |
| `2.x` | Supported / 支持 |
| `1.x` legacy PHP release | Not supported / 不再支持 |

## Reporting a vulnerability / 报告漏洞

Do not disclose exploit details in a public issue. Use GitHub's
[private vulnerability report](https://github.com/soulteary/Error-Tracer/security/advisories/new)
when it is available. If the private form is unavailable, open a minimal issue
requesting a private maintainer contact without including the vulnerability,
credentials, production data, or proof-of-concept details.

请勿在公开 Issue 中披露利用细节。优先使用 GitHub 的
[私密漏洞报告](https://github.com/soulteary/Error-Tracer/security/advisories/new)。
如果该表单不可用，请只创建一个请求私下联系维护者的简短 Issue，不要附带漏洞、
凭据、生产数据或概念验证细节。

A useful private report includes the affected version, deployment assumptions,
impact, reproduction steps, and a proposed mitigation if known. Remove secrets
and personal data before sending it.

有效的私密报告应包含受影响版本、部署前提、影响、复现步骤，以及已知时的缓解建议；
发送前必须移除密钥和个人数据。
